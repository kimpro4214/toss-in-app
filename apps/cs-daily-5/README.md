# 오늘의 CS 5

한국어 개발자 복습 앱. **17과목·510문제**, 과목별 쉬움/중간/어려움 10개씩이다. React 18 + TypeScript + Vite + TDS + 앱인토스 SDK로 구현했다.

브랜치는 `main`(릴리스), `dev`(통합), `feat/cs-daily`(기능 개발)로 나눈다. 기능 변경은 `feat/cs-daily → dev`, 릴리스는 `dev → main` PR로 반영한다. `idea.md`는 Git에 포함하지 않는다.

## 실행

이 폴더에서 Node.js 22.12 이상 또는 24 이상을 사용한다.

```powershell
npm ci
npm run dev
```

브라우저: `http://127.0.0.1:5173`. 설치 버전은 `package-lock.json`으로 고정한다. SDK **3.7.0**, TDS 두 패키지 **2.4.1**이다. 승인 계획의 SDK 3.0.0은 npm에 게시되지 않아 설치 가능한 3.x를 사용했다. 기존 샌드박스 대신 토스 앱 QR 테스트가 필요하다.

## 구현 범위

- 전체 랜덤: 서로 다른 5과목 / 집중: 선택 과목 5문제.
- 하루 기본 세트 한 개, 한국 날짜, 문제 목록 고정, 미완료 세트 이어하기.
- 난이도 선택과 과목별 진행, 부족하면 다음 단계, 소진하면 복습 표시.
- 4지선다·즉시 해설·각 오답 이유·환경·출처, 코드 가로 스크롤과 직접 작성한 SVG.
- 답 제출마다 저장. 저장 실패 시 답이 확정된 것처럼 보이지 않는다.
- 최초 답·점수 유지, 무료 오답 복습, 과목 필터.
- 기본 완료 후 하루 한 번 광고 보상으로 **새 3문제**. 3개를 확보하지 못하면 숨긴다.
- `userEarnedReward`에서만 지급하고 중복 이벤트를 무시한다. 실패·취소·미지원은 기본 학습에 영향을 주지 않는다.
- 토스에서는 익명 식별키별 SDK Storage, 브라우저에서는 localStorage. 기기 간 동기화는 없다.
- 토스 Safe Area·뒤로가기·닫기·외부 출처 열기·화면/클릭/광고 노출 분석 API 연결.

## 검사

```powershell
npm run validate:content
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run check:release
```

브라우저 검사는 설치된 Windows Chrome을 기본 사용한다. 다른 환경은 `PLAYWRIGHT_CHROME_PATH`를 해당 실행 파일로 지정한다. 콘텐츠 검사는 510개, 각 과목/난이도 분량, ID·질문 중복, 선택지·정답, 해설·출처·검수 기록, GoF 23개 패턴, 그래픽스 20+엔진 10을 확인한다. 단위 검사는 출제·날짜·미완료 예약·진행·중복 제출·복습·보상·철회와 계산/JavaScript 예시를 확인한다. 브라우저 검사는 학습 완료·복원·오답·저장 실패·잘못된 기록·광고 정상/취소/로드 실패/표시 실패/중복/새 문제 소진을 확인한다.

`node scripts/check-sources.mjs`는 공개 출처 링크 접속을 검사하고 `reports/sources.json`에 남긴다. HTTP 성공은 문항의 정답을 증명하는 검사가 아니다. 문항은 직접 작성해 참조 조건과 정답·오답을 대조한 **1차 검수** 상태이며, 외부 전문가의 독립 검수나 실제 사용자 난이도 보정은 아직 하지 않았다. 경쟁 앱의 문제은행은 복제하지 않았다.

원고 직렬화 스크립트 `scripts/author-*.mjs` 실행 후에는 `node scripts/enrich-sources.mjs`도 실행한다. 배포 데이터의 원본은 `src/content/*.json` 17개이다. ID는 재사용·변경하지 않는다. 철회 문항은 기존 JSON에 `active:false`로 보존하여 기록과 해설을 유지하고 새 출제에서 제외한다. 저장 스키마 미지원이나 잘못된 기록은 오류로 표시하며 자동 초기화하지 않는다.

## 개발 광고

**브라우저 개발 서버에서만** 모의 광고가 있다. URL에 아래 값을 붙이면 실패 상황을 재현할 수 있다.

| 쿼리 | 동작 |
|---|---|
| `?devAd=success` 또는 없음 | 보상 1회 |
| `?devAd=cancel` | 노출·닫힘만, 보상 없음 |
| `?devAd=load-failure` | 로드 실패 |
| `?devAd=show-failure` | 표시 실패 |
| `?devAd=duplicate` | 보상 이벤트 중복, 지급은 한 번 |

`import.meta.env.DEV` 분기에서만 불러오므로 출시 번들에는 모의 코드가 포함되지 않는다. `.ait`의 실제 광고를 검증한 것으로 해석하면 안 된다.

## 토스 출시 전 남은 작업

현재 콘솔 appName·보상형 광고 그룹 ID가 없다. 기본 `cs-daily-5.ait`는 **로컬 패키징 확인용**이며 심사 제출·공개 배포하지 않았다.

1. 사업자/정산 및 앱 등록을 하고, 콘솔의 실제 appName과 보상형 adGroupId를 확보한다.
2. `.env.example`을 `.env.local`로 복사하고 실제 값을 넣는다. `.env.local`은 Git 제외다.
3. `npm run build`로 새 이름의 `.ait`를 만들고 `npm run check:release`를 실행한다. 설정 검사 통과는 실기기 검증 완료를 뜻하지 않는다.
4. Android·iOS 토스 앱 QR에서 기본 학습·강제 종료 복원·뒤로가기/닫기·Safe Area·코드/SVG·출처 열기·실제 광고 지급/취소/복귀를 확인한다.
5. 콘솔 심사 후 출시하고 실제 DAU·D1/D7·완료율·광고 노출/보상/정산을 확인한다. QR 테스트에서는 실제 분석 데이터가 수집되지 않는다.

현재 실제 광고 검증, 실기기 QR, 심사, 실제 매출 검증은 **미완료**다. 초기에는 결제·구독·AI 튜터·커뮤니티·코드 채점을 제공하지 않는다.
